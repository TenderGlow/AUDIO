无边框、始终置顶的悬浮窗：停在「解题」上 1.2 秒自动抓取当前屏幕，交给 **DeepSeek** 流式解题，
思考链不显示，只留答案与解析。

界面上**不加任何颜色、不加边框、不写任何说明文字**——只有与底色同源的小字。

**四个按钮，全部"悬停到秒自动生效，点击无效"，无任何动态效果**
（不填色、不描边、不画进度环、悬停不变色；按钮文字按可用宽度自动缩放，始终完整）：

| 按钮 | 默认时长 | 行为 |
| --- | --- | --- |
| 解题 | 1.2s | **每点一次 = 开一个新会话**：暂存了页面就把攒下的页面一次性全发出去；没暂存就当场抓当前屏幕发一次。发送前上一轮的缓存全部清零 |
| 加页 | 0.9s | 抓当前屏**只缓存不发送**（最多 4 页）；按过一次后「解题」变「发送」、「重置」变「取消」 |
| 重置 / 取消 | 0.9s | 开一个全新会话：正文、思维链缓存、已暂存页面（含临时图片文件）全部清空 |
| 退出 | 2.0s | 保存凭据并退出 |

顶栏右侧另有 **「复制」**（0.8s）——答案唯一的出口，流式输出中途也能复制已出的部分。

**后台热键**（界面上不显示、不做任何说明，默默执行）

| 按键 | 行为 |
| --- | --- |
| `Ctrl+Alt+0` | 显示悬浮窗 |
| `Ctrl+Alt+1` | 隐藏悬浮窗 |
| `Ctrl+Alt+Q` | **彻底退出**（窗口被藏起来时的救命出口） |

用 `Ctrl+Alt` 是为了避开 Chrome 的 `Ctrl+1`（切标签页）、`Ctrl+0`（恢复标签页）等快捷键。想换在 `audio/config.py` 的 `hotkey_show` / `hotkey_hide` 里改一行即可，支持 `Ctrl` / `Alt` / `Shift` 任意组合 + 一个字符。

**发送机制**：攒够 4 页后（`max_pages`），「解题」已经变成「发送」，点它就把这 4 张图**一次性**发给后端；
消息体里每张图都带「第 N 页截图：」标签，模型据此按页码 + 题号作答。没有暂存页面时，「解题」= 当场抓一屏直接解题。

**回答格式**：模型按「第 N 页 · 第 M 题」标注 → 【答案】→ 【简析】，简析**最多两句话**，不展开推导。

**性能**：正文用**增量换行**——测量和绘制共用同一张行表，只处理新增字符，且每帧只画看得见的行。

- 5000 次流式追加（1 万字符）：**47ms**；80000 字符 / 7500 次追加：**188ms**（25µs 一次）
- 因为滚动范围与绘制同源，**永远不会滚过头出现空白**（原来两者不一致，是"往下滚一片空白"的根因）
- 悬停进度线 20fps，且进度变化不足 2% 不重绘

**关于"吐字慢"**：实测 DeepSeek 的**吐字速度是 562 字/秒**（290 字只要 0.5 秒），慢的是前面那 4.1 秒思考——那是 `reasoning_effort = "high"` 的代价。想要更快，把 `audio/config.py` 的 `reasoning_effort` 改成 `"low"`（约 1~2 秒出答案，思维链变短）。

**防录屏 / 防截屏**

- 窗口带 `SetWindowDisplayAffinity(WDA_EXCLUDEFROMCAPTURE)`：这是**硬保证**，本地照常可见，
  但不会被任何截图 / 录屏 / 屏幕共享收进去。
  *实测：同一窗口设 0x11 后，BitBlt 抓到的像素从 40000 降到 0。*
- `showEvent` 每次显示都重新设置一遍——`setWindowFlag` 会重建原生窗口句柄，affinity 会丢。
- 额外还有一层主动隐藏：每 700ms 检查一次有没有录屏 / 截屏工具在跑（OBS、XSplit、Bandicam、
  Snipaste、Xbox Game Bar 等），一旦发现就先藏起来，撤掉后自动回来。
  这一层是为了避免某些工具把窗口画成黑块或残影。

## 不用了怎么关掉

程序不在任务栏、也不在托盘，所以留了三条通道：

| 方式 | 怎么做 |
| --- | --- |
| **界面内** | 悬停「退出」2 秒 |
| **全局热键** | `Ctrl+Alt+Q` —— 窗口被藏起来时的救命出口 |
| **外部脚本** | 双击 `停止Audio.bat`（`python audio\shutdown.py stop`） |
| **彻底不启动** | 双击 `取消开机自启.bat`，删掉启动文件夹里的自启项 |

原理：启动时把 pid 写进 `%APPDATA%\Audio\audio.pid`；停止前核对"这个 pid 还在，且它确实持有
标题为 Audio 的窗口"，两者都对才动手，不会误杀你其它 python 程序。
不想用脚本的话，任务管理器里结束那个 `pythonw.exe`（在"详细信息"标签页）也一样。

## 开机自启

- `开机自启.bat`：以 `pythonw`（无黑窗）方式启动。
- `安装开机自启.bat`：把它复制到当前用户的"启动"文件夹，**开机自动运行**；
  卸载用 `取消开机自启.bat`（就是删掉 `%APPDATA%\Microsoft\Windows\Start Menu\Programs\Startup\开机自启.bat`）。

> 任务管理器里显示的是进程名 `pythonw.exe`，这是它的真实身份。我们不做把它伪装成「Windows 更新(2)」这类系统进程的做法——那是为了让人看不出它在运行。如果你要的是"不显眼"，可以用上面的自启脚本，或给程序加个托盘图标最小化。

## 本地回环代理（做什么、不做什么）

`use_local_proxy = True` 时，主程序启动会拉起一个**独立的**代理进程，主程序只和 `127.0.0.1` 通信。

**做到的事**（实测读 netstat 连接表）：

| 进程 | 回环连接 | 外网连接 |
| --- | --- | --- |
| 主程序 | 99 条 → `127.0.0.1:8901` | **0 条** |
| 代理进程 | 99 条 | 24 条 → 上游 443 |

另外 API Key 只存在于代理进程内存里，主程序不接触。

**没做到的事，说清楚**：上游那条连接**搬到了代理进程，并没有消失**。想在资源监视器里
彻底查不到，只有内核 hooking / 驱动过滤，那是规避系统审计，不做。
所以这一层的准确说法是「隔离」，不是「隐藏」。

代理必须独立进程：进程网络栈互相隔离，代理若跑在主程序进程内，两者共用同一份连接表，
实测主程序照样看得到上游连接，代理等于没起作用。

## 输出结构

```
┌ ● ──────────────────── 已加页 2/4 ┐   ← ● = 小圆圈(悬停2秒跟随移动)
│                ▲                 │   ← 正文上边框正中间的向上箭头
│ 答案正文                        │      （悬停 = 持续向上滚，不快不慢）
│                ▼                 │   ← 正文下边框正中间的向下箭头
│ 解题  加页  重置  退出            │   ← 每个按钮底部有一条细进度线
└────────────────────────────────────┘
```

箭头尺寸与左上角小圆圈一致（14×14），颜色、透明度与正文完全相同；每 50ms 滚 10px（约 200px/s），
不会一下子冲到顶或底，滚到头自动停。正文也可直接用鼠标滚轮翻阅（一格约 45px）。

DeepSeek 的 `reasoning_content`（思维链）**只在后台自己推理，界面任何位置都不显示**。

**颜色统一**：正文、状态、四个按钮、按钮进度线、小圆圈、上下箭头共用同一支"墨水"
——同一个颜色、同一档透明度（`alpha(前景色, 8%)`），没有任何彩色区分。

## 已知限制

- 正文区是拖动窗口的热区，不支持鼠标框选；把鼠标移到窗口外再拖标题条可移动。
- 抓屏默认只抓**鼠标所在的那块显示器**（双屏时不会把两屏拼成一张导致题目像素被摊薄）。
  想抓整个虚拟桌面：把 `config.py` 里 `current_monitor_only` 改成 `False`。
- 抓屏时窗口通过 `SetWindowDisplayAffinity` 把自己排除在外；浏览器在前台时还会先隐藏再截，截完自动回来。
- `settings.json` 里的 API Key 用 **Windows DPAPI 加密**后落盘（只有当前账户能解）。
  换账户或换机器后解不开，程序会打印提示并回退到 `config.py` 里的默认值。
  旧的明文文件在下次启动时会自动升级成密文。
